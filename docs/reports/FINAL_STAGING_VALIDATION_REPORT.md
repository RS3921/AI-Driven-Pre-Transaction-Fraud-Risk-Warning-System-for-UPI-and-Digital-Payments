## 4. Documented Staging & Deployment Restrictions

To proceed to a controlled pilot deployment, the following operational restrictions and prerequisites must be satisfied:

1. **Git Repository Tagging:**
   - Initialize git tracking at the workspace root (`C:/Users/Raveena/Downloads/UPI-Fraud-Guard/UPI-Fraud-Guard-Multilingual-Improved`) and push tag `v2.6.0-RC1` associated with commit revision `7963912389143022f18e3c4f43cd62bd4166edc6` to the official remote repository.
2. **Model Governance & Retraining Lock:**
   - Candidate model deployment is locked to the active baseline (`models/transaction_model.joblib`). Retraining and deploying new candidate transaction models is strictly prohibited until a timestamped transaction log is acquired to enable temporal cross-validation.
3. **External CTI Feed Credentials:**
   - Production deployment requires injecting valid API keys for AlienVault OTX (`OTX_API_KEY`) and AbuseIPDB (`ABUSEIPDB_API_KEY`) in `.env`. Unconfigured feeds will safely log status `"Unconfigured"` without throwing exceptions.
4. **TLS & Non-Loopback Network Binding:**
   - When binding `UPI_FRAUD_GUARD_HOST` to a non-loopback interface (e.g. `0.0.0.0` or host IP), valid PEM-encoded TLS certificate (`UPI_FRAUD_GUARD_TLS_CERT`) and private key (`UPI_FRAUD_GUARD_TLS_KEY`) files must be mounted.
5. **Physical Android Device Smoke Testing:**
   - While Android APK build (`:app:assembleDebug`) and API contracts were verified 100%, physical device camera barcode scanning must be verified on hardware during the initial pilot phase.
